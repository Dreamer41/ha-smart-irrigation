# ZoneFlow 1.6.4 — Rain gauge fix and measuring flow by volume

**What's changed**

- **Rain amounts that were too high are fixed.** A zone with a rain gauge could
  count rain that never fell: the first tip after the *Rain Gauge mm per Tip*
  setting differed from the one the stored rain was recorded with added about
  4 mm (all tips so far x the difference). That happened when the slider was
  moved, and also after a restart that read the default value before the saved
  one was restored. ZoneFlow now rescales what it has stored to the setting in
  use, so only real tips make rain. A wrong amount already stored fades out of
  the 14-day window by itself.
- **New: Configure → Flow rate: measure it by the litres a service run gave.**
  For zones without a flow meter: press a Service Run button (15 minutes is the
  most accurate), catch or read the water (a bucket, a barrel or a water
  meter), and enter the minutes, the litres and the area. The result is the
  zone's **average**. For a precise result, every emitter on a zone's valve
  should be the same type and flow; put different emitters on separate valves
  (separate zones).
- Deleting the Weather Underground entry now switches "use Weather
  Underground" off in the zones that used it, so manual rain is offered again.
- The integration's `iot_class` is now `cloud_polling`, because Weather
  Underground calls a cloud service (it is optional).

## Update your dashboard

No dashboard changes needed. After updating, do a hard refresh of the browser
(Ctrl+F5) to load the new card.

## After updating

Restart Home Assistant. If a zone's rain numbers were too high, they correct
themselves as the old amounts leave the 14-day window.
